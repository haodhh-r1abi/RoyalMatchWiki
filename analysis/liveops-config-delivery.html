Config từ xa đi xuống máy người chơi như thế nào

Server gửi config qua đường nào, máy lưu ở đâu, khi nào tải lại, và chuyện gì xảy ra khi mất mạng hay file hỏng.

📡 LiveOpsPingHttpCommand, RegisterHttpCommand, UpdateUserProgressHttpCommandTimeHelper.SendPing, BackendHttpService*Manager.UpdateInfo + *ConfigHelper (ServerEventConfig / UserEventConfig)EventDependencyManager, MissionEventsHelperRemoteConfigManager (level vá), SlbMoveConfigHelper, RemoteRoyalBundleManager, ProfileSkinBundleManagerSQLite app_pFiles/App và app_pFiles/U_<userid>

Bài này đi theo đường của config live-ops từ server tới máy: 3 lệnh server, 6 file CDN, 2 file save SQLite. Đọc khoảng 8 phút. Nên đọc trước các bài liveops-client-settings (cờ bật/tắt) và liveops-ab-testing (nhóm thử nghiệm), vì hai thứ đó cũng đi chung đường này.

Kết luận: Đường config của Royal Match tiết kiệm và chịu mất mạng tốt. Máy báo version đang giữ, server chỉ gửi lại phần bị lệch, mọi thứ lưu sẵn trong SQLite và còn 26 file mặc định trong game để chống trống. Điểm trừ: config Seasonal Card Collection (25.723 ký tự) bị gửi lại sau mọi ván, và config nằm rải ở quá nhiều chỗ nên khó kiểm tra máy đang chạy bộ nào.
Cách đọc ví dụ
  • ✅ Giá trị thật: lấy thẳng từ code, config server thật, save hoặc ảnh chụp khi chơi.
  • 🧪 Ví dụ minh họa: con số đầu vào giả định để thấy cơ chế chạy; cách tính trong ví dụ là cách tính thật trong code.
  • Tên kỹ thuật (class, method, key) để trong ngoặc hoặc ở dòng bằng chứng, để tra code khi cần.

Tóm tắt nhanh

  • Có ba lệnh server mang config. Register khi cài lần đầu, Ping mỗi lần mở hoặc quay lại app, UpdateUserProgress sau mỗi lần bắt đầu, thắng, thua một màn. Chỉ Ping mang cờ hệ thống (ClientSettings, Flags, MaxLevel); Ping và UpdateUserProgress mang thông tin event.
    Ví dụ ✅ Ping ngày 09/09 (SyncId 26) trả 14 event và 19 cờ; mỗi UpdateUserProgress sau ván trả 13 event, không có cờ.
  • Máy khai version, server chỉ gửi phần lệch. Lệnh Ping có 50 ô version, lệnh UpdateUserProgress có 44. Event nào version trùng thì server chỉ gửi id và thời gian còn lại, không gửi nội dung.
    Ví dụ ✅ Ngày 08/09 máy giữ Ancient Adventure bản 291. Ngày 09/09 server lên bản 292 → Ping gửi kèm nội dung bản 292; 12 event còn lại trùng version nên không kèm gì.
  • Có một chỗ bị gửi thừa. Máy không bao giờ khai version của Seasonal Card Collection, nên server gửi lại cả mùa sau mỗi ván (suy luận từ việc ô này luôn trống).
    Ví dụ ✅ Cả 21 lần UpdateUserProgress đã giải mã đều kèm config thẻ mùa dài 25.723 ký tự, dù version 305 không đổi.
  • Config event có hai lớp. Lớp chung cho cả đợt (ServerEventConfig) và lớp riêng từng người (UserEventConfig, về khi mở hoặc vào event).
    Ví dụ ✅ Hidden Temple đợt 174 lưu ServerEventConfig bản 453 (10 stage); Team Tournament có ô riêng UserEventConfig chờ người chơi vào đội.
  • Mất mạng vẫn chơi được. Mọi config đã nhận nằm trong SQLite; chưa từng nhận thì dùng 26 file mặc định trong game. Event không có file mặc định (Ancient Adventure, Daily Rewards, thẻ mùa, Team Tournament…) chỉ hiện khi đã có config server.
    Ví dụ 🧪 Người chơi bật chế độ máy bay: Balloon Rise vẫn chạy với 10 bậc đã lưu; một event mới chưa từng tải thì không hiện.
  • Nội dung nặng đi CDN riêng, có ETag và checksum. Level vá, bảng cộng nước SLB, giá Supercharge, danh sách bundle đều tải từ CDN và chỉ tải lại khi file đổi.
    Ví dụ ✅ Máy level 8 đã tải sẵn 81 level vá (7015–14499); bảng giá Supercharge lưu thành 6 ô SCOConfig2..7 = 4900 / 3900 / 3900 / 2900 / 1900 / 900 coin.
  • Build này không dùng Firebase Remote Config. Dòng log 'Remote configs will be activated.' là của bộ tải level vá (RemoteConfigManager), không phải Firebase. Bảng live-ops trong 06-Social-LiveOps-Analytics.md ghi nhầm chỗ này.
    Ví dụ ✅ FirebaseHelper chỉ có analytics, push token, AppCheck, Crashlytics; không có hàm fetch config.

Ảnh chụp minh họa (3)

Ảnh chụp từ game thật trên LDPlayer. Bấm ảnh để phóng to, phím ← → để chuyển ảnh.

Luồng hoạt động (15 bước)

Tóm lại: mở app → đọc cache SQLite → Ping / ván khai version đang giữ → server gửi phần lệch → máy ghi đè cache → CDN kiểm ETag, tải file mới → tính năng dùng bản mới

  1. 1
    Mở app, đọc cacheClient
    Mỗi tính năng đọc config đã lưu. Chưa có thì đọc file mặc định trong game.
    Ví dụ ✅ Save có 49 khoá ở file App và 95 khoá + 45 bảng ở file người chơi; Event Dependency đọc 'LoadConfig V:291' thay vì file mặc định.
    EventDependencyManager.LoadConfig; HiddenTempleConfigHelper.LoadServerConfig; facts/runtime/_backup_lvl8
  2. 2
    Đăng ký nếu chưa có tài khoảnServer
    Thử tối đa 15 lần. Server trả tiến độ, nhóm AB, vị trí, phân khúc.
    Ví dụ ✅ Vị trí lưu thành 'Hanoi§§VN'; 52 nhóm AB được ghi vào bảng AbTestTableItem.
    UserManager.RegisterIfNeeded (MaxRegisterTryCount 15); RegisterHttpCommand.UpdateUserData / UpdateLocationData
  3. 3
    Gửi PingClient
    Ping gửi khi mở app hoặc quay lại app. Không gửi khi đang mua hàng, đang đăng nhập, vừa xem quảng cáo.
    Ví dụ ✅ Ping 08/09 khai 15 version khác 0, kèm điều khoản bản 5 và ngôn ngữ English.
    TimeHelper.SendPing (PingSendReason AppStart/AppResume); decoded_old/067_3_PingRequest.json
  4. 4
    Gộp nhiều lệnh vào một góiClient
    Gói gửi lên game-server, chờ tối đa 12 giây. Bật cờ Cloudflare thì dùng tên miền dự phòng. Giờ máy chưa được server xác nhận thì lệnh khác bị thay bằng Ping.
    Ví dụ ✅ Gói 09/09 gồm Ping + GetFriends + GetSystemMessages trong một lần gửi.
    BackendHttpService.SendToEndpoint(timeOut 12), ShouldUseCloudflare; ResponsesType trong 004_1_PingResponse.json
  5. 5
    Đọc tham số chungClient
    Ping mang level tối đa, theme màn chờ, level mở League, 64 bit Flags, cờ hệ thống, điều khoản.
    Ví dụ ✅ MaxLevel 14500, RequiredLevelForLeague 14501. Chi tiết cờ: bài liveops-client-settings.
    PingHttpCommand.ProcessSettings
  6. 6
    Đọc nhóm AB, yêu cầu của server, tiến độClient
    Cập nhật nhóm AB; làm theo yêu cầu đặc biệt (gửi log, gửi lại dữ liệu); so tiến độ; rồi phát thông tin cho từng event.
    Ví dụ ✅ Ping 09/09 không có yêu cầu đặc biệt (RequestedOperation = None).
    PingHttpCommand.ProcessUserData; RequestedOperationType
  7. 7
    Mỗi event nhận phần của mìnhClient
    Id đợt mới thì xoá tiến độ cũ. Giờ kết thúc = thời gian còn lại + giờ máy. Có nội dung mới thì ghi đè, không có thì giữ bản cũ.
    Ví dụ ✅ Hidden Temple nhận RemainingTime 151.992.896 ms → kết thúc 11/09 15:00; nội dung trống vì vẫn là bản 453.
    HiddenTempleManager.UpdateInfo; HiddenTempleConfigHelper.UpdateServerConfig
  8. 8
    Ghi vào SQLiteClient
    Mỗi event một bảng (Id/Value) trong file người chơi; config hệ thống nằm ở file App.
    Ví dụ ✅ BalloonRiseTableItem: ServerEventConfig (406 ký tự), version 414, id đợt 323, hạn kết thúc.
    U_2712389101.*TableItem; App.KeyValue (RoyalPassConfig, PinataConfig, SLBMoveConfig)
  9. 9
    Config riêng từng ngườiServer
    Khi người chơi mở hoặc vào event, server gửi thêm target/thưởng riêng. Muốn ép tải lại thì máy đặt version về 0.
    Ví dụ 🧪 Người chơi vào Team Tournament → server gửi UserEventConfig riêng cho đội của họ; tài khoản test chưa có đội nên ô này trống.
    HiddenTempleConfigHelper.UpdateUserConfig / ResetUserConfigVersion; TeamTournamentTableItem
  10. 10
    Config hệ thống ngoài eventServer
    Nhóm event chạy chung, sửa nhiệm vụ lỗi, mời bạn, nước có thanh toán ngoài, phân khúc offer.
    Ví dụ ✅ Nhóm event bản 291, sửa nhiệm vụ bản 1, mời bạn bản 5, popup mạng xã hội bản 7 (từ level 300).
    EventDependencyManager.SaveConfig; MissionEventsHelper.TryUpdateMissionOverrideConfig; GetSystemMessagesResponse.SocialPopup
  11. 11
    Sau mỗi vánClient
    UpdateUserProgress khai lại 44 version; config đổi được nhận ngay ván sau, không chờ lần mở app tới.
    Ví dụ ✅ Thắng màn 10 → gói SyncId 36 gửi lên, phản hồi mang lại 13 event.
    UpdateUserProgressHttpCommand; facts/runtime/level-protocol.md
  12. 12
    CDN: level váServer
    Tải danh sách level vá theo version app, tải từng file, kiểm checksum, ghi tên vào save. Khi nạp màn, bản vá được ưu tiên.
    Ví dụ ✅ 81 file; 65 file thuộc 14000–14499 (khối level mới nhất).
    RemoteConfigManager.GetVersionConfig / Download / OnFileSaveCompleted; App.RemoteDownloadedLevelNames
  13. 13
    CDN: bảng sốServer
    Bảng cộng nước SLB, giá Supercharge, bảng điểm Clash of Champions, danh sách level Ocean Odyssey; chỉ tải lại khi ETag đổi.
    Ví dụ ✅ Bảng SLB có 5 nhóm (46 / 111 / 84 / 53 / 12 level).
    SlbMoveConfigHelper.DownloadConfig; cdn_configs/*
  14. 14
    CDN: bundleServer
    Danh sách bundle động và cosmetic động; bundle theo lịch có thể bị server dừng; MaxLevelForBundle quyết định khối 100 level nào được tải.
    Ví dụ ✅ 240 bundle puzzle, 122 cosmetic; MaxLevelForBundle 14301 → khối 14301–14400.
    RemoteRoyalBundleManager (MaxDownloadTry 3); ProfileSkinBundleManager; LevelManager.UpdateMaxLevelForBundle
  15. 15
    Tính năng dùng bản mớiPlayer
    Event chỉ hiện khi đủ bundle và qua lớp nhóm event. Lần mở sau, kể cả offline, vẫn dùng bản đã lưu.
    Ví dụ 🧪 Sửa thưởng Balloon Rise trên server lúc 10:00 → người chơi thắng một màn lúc 10:05 là thấy thưởng mới.
    AEventManager.IsAllBundlesDownloaded; EventDependencyManager.ManualUpdate

Lưu ở đâu trong máy

Tóm lại: file App giữ config chung → file người chơi giữ event và tiến độ → bảng riêng theo máy giữ nhóm event

  • File App (dùng chung cho máy). Level tối đa, level mở League, cờ Cloudflare, cờ tắt mua hàng, config Royal Pass / Pinata, bảng SLB, giá Supercharge, danh sách bundle, 6 ETag.
    Ví dụ ✅ MaxPublishedLevel 14500, MaxPublishedEpisodeBundleStartLevel 14301, RequiredLeagueLevel 14501, PurchaseDisabled 0.
  • File người chơi. Config Ladder / Madness / sửa nhiệm vụ, hộp thư, cờ log, phân khúc, mỗi event một bảng.
    Ví dụ ✅ LadderOfferConfig bản 327, UserSegmentVersion 1134, AbTestTableItem 52 hàng.
  • Bảng theo máy. Nhóm event chạy chung giữ lại cả khi đổi tài khoản.
    Ví dụ ✅ EventDependencyConfig bản 291.
  • Save không mã hoá. Đọc được bằng sqlite3 trên máy root; server vẫn là bên quyết định level và coin.
    Ví dụ ✅ Toàn bộ số liệu trong bài này đọc thẳng từ save.

Những điểm lạ đáng biết

  • Ô AB đời cũ vẫn được gửi. Ping còn mang AbTestData/2/3 dạng bit, máy không đọc nữa.
    Ví dụ ✅ AbTestData = 8933532008448; gói gửi lên luôn là [0, 0, 0].
  • Schema giữ nhiều ô 'Deprecated'. Giúp app cũ không vỡ, đổi lại gói tin mang theo ô thừa.
    Ví dụ ✅ DeprecatedSegmentOfferInfo, DepreciatedLeagueConfig, DeprecatedLightningRushInfo.
  • Phân khúc tính lại theo ngày (suy luận). Version phân khúc tăng đúng 1 sau một ngày.
    Ví dụ ✅ 1133 → 1134 và 1333 → 1334 giữa 08/09 và 09/09.
  • Level vá đẩy cho cả người mới. Dễ vận hành, nhưng tốn tải với người chưa cần.
    Ví dụ ✅ Người chơi level 8 đã tải bản vá của level 14499.

Đánh giá

Thang 1–5 (với tiêu chí rủi ro, 5 = rủi ro cao). Trung bình: 3.8.

Tiêu chíĐiểmNhận xét
Tiết kiệm băng thông
4/5		12/13 event mỗi ván không phải gửi nội dung. Trừ 1 điểm vì thẻ mùa gửi lại 25.723 ký tự mỗi ván.
Chịu mất mạng
4/5		Cache + 26 file mặc định. Event không có file mặc định thì biến mất khi offline, đây là chủ ý.
Tốc độ đổi nội dung
5/5		Đổi config có hiệu lực ngay ván sau; từ 09/09 tới 06/10 level tối đa tăng từ 14500 lên ít nhất 14700 mà không cần bản app mới.
Dễ kiểm tra máy đang chạy bộ config nào
3/5		Config nằm ở 3 lệnh server, 6 file CDN, 2 file save, 4 kiểu bảng; không có một 'danh sách version' chung.
Rủi ro config sai (5 = cao)
3/5		Config server thay hẳn file mặc định; chỉ CDN có checksum. Một JSON lỗi làm hỏng event tới khi server đổi version.
Điểm mạnh
  • Một khuôn chung (id, thời gian còn lại, version, nội dung) cho mọi event: thêm event mới không phải đổi đường tải.
  • Số liệu nhẹ đi lệnh server, file nặng đi CDN có ETag: đúng chỗ.
  • Config về sau mỗi ván, không phụ thuộc người chơi đóng/mở app.
Điểm yếu
  • Thẻ mùa thiếu version trong lệnh gửi lên.
  • Nhiều ô cũ không dùng vẫn nằm trong gói tin.
  • Save không mã hoá.
Rủi ro
  • Server dùng lại một số version cũ → máy không bao giờ tải bản sửa.
  • Một file CDN dùng chung cho mọi nhóm AB: sửa sai một dòng ảnh hưởng cả nhóm ngay lần mở app sau.
  • Server lỗi đúng lúc event không có file mặc định → event biến mất giữa đợt.
Đề xuất
  • Gửi version thẻ mùa, hoặc đưa phần cố định của mùa lên CDN: bớt khoảng 25,7 nghìn ký tự mỗi ván.
  • Thêm 'danh sách version' trong Ping và ghi vào log: CS nhìn một dòng là biết máy chạy bộ config nào.
  • Kiểm JSON trước khi ghi đè cache; lỗi thì giữ bản cũ và gửi analytics lỗi config.
  • Chỉ đẩy level vá trong khoảng [level hiện tại, level hiện tại + 500] cho người mới; ví dụ người level 8 không cần bản vá level 14499.
  • Game tương tự: dùng đúng khuôn 'khai version, gửi phần lệch', và bắt version chỉ được tăng.

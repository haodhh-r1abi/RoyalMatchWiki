Phân tích chi tiết từng gói IAP — Royal Match

28 nhóm / 157 gói IAP: luồng mua, điều kiện tồn tại, phân khúc

💰 Sale & kiếm tiền

157 product id com.dreamgames.royal.<group>.<n> (28 nhóm), giá USD mặc định compile sẵn trong client (PurchaseHelper.DefaultProductsDictionary); giá thật lấy từ Google Play / Xsolla lúc chạy, nội dung gói do PricingStrategies + config server quyết định. Danh sách đầy đủ: appendix/iap-products.md.

Cách đọc ví dụ
  • ✅ Giá trị thật: lấy thẳng từ code, config server thật, save hoặc ảnh chụp khi chơi.
  • 🧪 Ví dụ minh họa: con số đầu vào giả định để thấy cơ chế chạy; cách tính trong ví dụ là cách tính thật trong code.
  • Tên kỹ thuật (class, method, key) để trong ngoặc hoặc ở dòng bằng chứng, để tra code khi cần.

1. Luồng mua & xác thực backend (chung cho mọi gói)

1. Hiển thị: manager tương ứng (Shop/Offer/Pass…) dựng gói qua APricingStrategy → chọn chiến lược giá theo segment (DefaultPricingStrategy / IncreasedPricePricingStrategy / LessContentPricingStrategy(V2)), lấy giá hiển thị từ store.

2. Bấm mua → PurchaseManager.StartPurchase → NativeService.StartPurchase (Google Play Billing) hoặc PaymentSelectionDialog → Xsolla (web, từ level 52, có ExternalPaymentFirstPurchaseBonusHelper).

3. Xác thực server: PurchaseVerificationHttpCommand (RequestType PurchaseVerification) gửi receipt → server verify → trả gói. Nếu đang bảo trì: PurchaseInMaintenanceModeHttpCommand. Lỗi → RetryPurchaseStrategy.

4. Thành công: OnPurchaseSuccess → cộng nội dung qua InventoryPackage (một lần, log "Add … to inventory"); cập nhật highestBoughtBundle/SinglePackage trong BasicUserData.UserData; first‑purchase bonus (FirstPurchaseBonusHelper, PaymentCoinBonusConfig).

5. Analytics: Spending, PurchaseSuccess/Fail/VerificationFinish với payment_store, revenue, transaction_id, product_id, offer_type, offer_segment.

Chống "mua hớ" / neo giá: FilteredAndSortedPackages(filterCoin, highestBoughtBundle, highestBoughtSinglePackage) ẩn gói nhỏ hơn gói đã từng mua (MinHighestBoughtBundleIndex..Max) → đẩy người đã chi lên bậc cao hơn. Nhãn Popular, BestValue; ưu tiên sắp xếp ShopBundlePriority=3000, ShopCoinPackagePriority=4000.

Điểm probe server (Phase 4): receipt giả/trùng transaction_id, product không eligible theo segment, mua khi maintenance, Xsolla path → xem server chấp nhận/khớp gói ra sao.

3. Cá nhân hoá giá & nội dung (price discrimination)

  • Chiến lược giá chọn theo UserOfferSegment + UserSpecialOfferSegment (server set): cùng một "slot" offer, người khác segment thấy giá khác / nội dung khác (IncreasedPrice cho người sẵn sàng chi, LessContent(V2) cho người nhạy giá).
  • Ladder/offer segment file (_3_20, _3_50, _6_20) = biến thể số bậc × ngưỡng theo nhóm.
  • First‑purchase bonus (coin ×) để phá rào mua lần đầu; conversionoffer nhắm riêng non‑payer.
  • Neo giá: ẩn gói nhỏ hơn gói đã mua ⇒ bậc giá trung bình tăng dần theo lịch sử chi.

4. Điều kiện tồn tại (tóm tắt)

Một gói IAP chỉ xuất hiện khi hội đủ: (1) feature unlock level đạt (bảng events‑overview), (2) event/offer đang active trong lịch server, (3) segment đủ điều kiện (server trả gói id phù hợp), (4) trigger ngữ cảnh (hết lượt → ego; vào level cực khó → ehl offer; có đội → team offer; mốc level → offer auto‑dialog), (5) trạng thái auto‑dialog chưa hết (AutoDialogState/LastSeenDate), (6) chưa vượt rào mua (filter theo highestBought). → Phần (2)(3) do server quyết định, sẽ probe ở Phase 4.
